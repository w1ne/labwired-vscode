# VS Code Model Catalog Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let a VS Code user choose a public model from the core catalog or select a local system YAML, then select firmware and save the existing `.labwired/lab.yaml` profile.

**Architecture:** Add a focused catalog module that fetches the core publisher's manifest and archive, verifies SHA-256, safely extracts the public `configs/` tree into the project cache, and returns chip names generated by core's existing `Catalog`. The existing native wizard then picks a chip or local YAML, picks firmware, and writes one portable profile only after all choices succeed.

**Tech Stack:** TypeScript, VS Code Quick Pick and progress APIs, Node HTTPS and crypto, `tar`, `js-yaml`.

---

## File map

- `src/modelCatalog.ts`: validate metadata, download and verify the bundle, cache it by core commit, safely extract it, and find or create a system manifest.
- `src/configWizard.ts`: add the catalog/local source step and select firmware after the model.
- `package.json`, `package-lock.json`: include the direct tar extraction dependency in packaged extensions.
- `src/test/unit/modelCatalog.test.ts`: verify manifest validation, checksum, safe extraction, cache reuse, and synthesized manifests against a local HTTP server.
- `src/test/suite/configWizard.test.ts`: verify the catalog and local YAML choices save correct relative paths and cancellation leaves the existing profile unchanged.
- `README.md`: add the short first-use flow and explain that firmware is selected separately.

## Task 1: Add a testable catalog downloader and cache

**Files:** Create `src/modelCatalog.ts`, `src/test/unit/modelCatalog.test.ts`; modify `package.json` and `package-lock.json`.

- [ ] Start a local HTTP fixture server in a unit test. Serve a manifest and a small `configs.tar.gz` containing `configs/chips/alpha.yaml` and `configs/systems/alpha.yaml`. Assert the installed cache path is `.labwired/models/<core-commit>/configs`, `chips` equals the manifest array, and the cached system file can be resolved.
- [ ] Run `npm run test:unit -- --grep "model catalog"`; expect failure because the catalog module does not exist.
- [ ] Add `tar` as a direct runtime dependency with `npm install --save tar`.
- [ ] Implement `installCatalog(rootPath, progress, token, baseUrl?)` and `findOrCreateSystemYaml(catalog, chip)`. Use manifest shape `{schema_version: 1, core_commit, archive: "configs.tar.gz", sha256, chips}`; reject invalid SHA/commit/name values and unexpected archive names.
- [ ] Verify archive SHA-256 before extraction. Preflight every tar entry, rejecting absolute paths, `..` traversal, and links; extract only the `configs/` root into a temporary sibling directory, then rename into the commit cache. Remove temporary files on failure or cancellation.
- [ ] When `configs/systems/<chip>.yaml` is missing, write a portable minimal manifest there with `name: <chip>`, `chip: ../chips/<chip>.yaml`, and `external_devices: []`, matching the core Catalog fallback.
- [ ] Run `npm run test:unit -- --grep "model catalog"`; expect all new tests to pass, including checksum mismatch, unsafe archive, and cache reuse cases.

## Task 2: Connect the catalog to the native model wizard

**Files:** Modify `src/configWizard.ts` and `src/test/suite/configWizard.test.ts`.

- [ ] Add a first native Quick Pick with `Choose from LabWired catalog` and `Select local model YAML`.
- [ ] For catalog selection, show cancellable notification progress while installing/reusing the bundle, then show a Quick Pick from the manifest's core-generated chip names. Resolve the selected system YAML from the installed tree.
- [ ] For local selection, retain the native YAML file picker. After either source selects a model, show the existing firmware picker and then preserve the current optional standard/custom DAP steps.
- [ ] Keep `.labwired/lab.yaml` untouched until the model, firmware, and optional DAP choices are complete. On catalog failure or cancellation, show `Select local YAML` and `Cancel` actions; selecting local opens the current YAML picker.
- [ ] Update existing wizard test pick queues to choose local YAML by default. Add host tests that choose a catalog chip and verify the model and firmware paths in the saved profile, and that catalog/local cancellation does not modify an existing profile.
- [ ] Run `npm test`; expect all existing and new extension-host tests to pass.
